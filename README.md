# 影展换厅后的放映介质接收与开场确认

资料联调站以本地合成资料模拟分别维护的业务来源。用 Node.js 22.23.4 启动，支持在同一进程中切换来源发布。启动后地址默认是 `http://127.0.0.1:4178`，可用环境变量 `PORT` 修改。

浏览器联调使用 Playwright 1.56.1。首次在新环境准备依赖时执行 `npm ci` 和 `npx playwright install chromium`。已有对应 Chromium 的环境可以直接运行。

```sh
npm run origin
npm test
```

`npm run origin` 为独立的来源服务。`npm test` 另起临时端口验证资料站，不需要预先启动来源进程。测试包含 Chromium 中的页面操作。

联调站的 `GET /_desk/releases` 返回发布名与当前档。值台可向 `/_desk/releases/发布名` 发送 POST 切换资料，发布名按 UTF-8 进行 URL 编码。可选档位为首发、换厅、新授权。切换后各来源从当前档的内容响应，业务数据以原接口的版本字段与时间为准。联调档位名称仅用于控制资料站。

## 来源协议

排期来自 `/schedule/roster`。每个 `show` 只列当前 `rev`，本地放映时间以 `zone` 解释，结束时间小于开始时间表示跨午夜。 `use` 区分正式场和试播。
授权交付从 `/portal/shows` 操作。页面有场次和用途选择，确认后显示组合号、清单版本、介质下载链接、摘要及设备授权的 UTC 区间。链接可能随发行窗口关闭，误用会返回 410。演练介质是短文本载荷。 `/terminals/imports` 按场次给终端实际导入回执，`/terminals/inventory` 反映是否可用。
`requests.json` 为值台接收的排片范围。页面上的设备证号均为虚构，资料没有真实影片或放映授权。

`sources/exchange.json` 保存联调站的来源记录和原件载荷，`sources/requests.json` 保存业务席可用的请求材料。材料中的单位、标识、组织及记录内容均为合成。

## 值台放映交接工具（`desk/`）

仅依赖 Node 内置模块，把上述来源串成一条可审计的交接链路。状态目录（原件缓存与 `state.json`）由调用方指定，与源码分离。

```sh
npm run origin                              # 另开终端启动来源
node desk/cli.mjs ./desk-data sync          # 按当前排期同步并逐场取件
node desk/cli.mjs ./desk-data list          # 开场名单：当前接受哪次确认、缺什么
node desk/cli.mjs ./desk-data show P14 正式场
node desk/cli.mjs ./desk-data resync P14 正式场        # 链接过期或排片改动后重新申请
node desk/cli.mjs ./desk-data handover P14 正式场 阿婉  # 接手放映员确认交接
node desk/cli.mjs ./desk-data history P14 正式场
node desk/cli.mjs serve ./desk-data --port 4180        # 值台网页
```

工具落实的判定规则：

- **时区与整场**：放映时间按排期 `zone` 把当地墙上时间换算为 UTC，结束早于开始按跨午夜处理；授权的 UTC 区间必须完整覆盖整场，边界相等视为覆盖。
- **组合与清单**：只认该场次、该用途授权页给出的组合号与清单版本；同片名不同组合（字幕版/无障碍版/试播短片）互不串用。同一份原件可被多个组合引用，缓存按 sha256 内容寻址复用，但某组合缺项时不能拿其他组合里的同名文件顶替，复用前后都重新核对摘要。
- **临时链接**：下载遇 410 不换源顶替，标记 `expired`，必须重新到该场次该用途的授权页申请；新链接交付内容与缓存摘要一致时仍可复用。
- **设备授权四要素**：组合号、设备证号、用途、起止时刻全部命中才算数；试播授权只覆盖试播场次，不能用于正式场；登记台把旧设备标记下线后，原厅授权不随换厅继承。
- **导入回执**：回执必须对得上当前厅设备、清单版本与用途；换播放终端或清单升版后旧回执不再满足条件。
- **交接确认**：介质、授权、回执全部满足才允许接手放映员确认，确认记录固化当时的 rev、厅、设备、组合版本、摘要、授权窗与回执号。换厅、换终端、拉长放映时窗会使旧确认失效（记录保留可查并注明原因），受影响场重新判断、重新确认；并行的另一厅未受影响时原确认继续有效。开场名单逐场指出当前实际接受的确认与具体缺口。
- **排片再变动**：每次同步都以排期当前 `rev` 与门户当前页面为准重建判定依据，避免拿着上一轮的“可开场”结论找片。

`npm test` 在来源资料站测试之外，另含 `test/desk.test.mjs`（核心规则）与 `test/desk-browser.test.mjs`（值台网页端到端：首发→换厅→新授权）。
